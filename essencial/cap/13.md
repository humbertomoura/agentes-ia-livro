@CHAPTER CAPÍTULO 13|Mão na massa: a encomenda do casamento|Um workflow que espera a aprovação, sobrevive a uma queda de energia e sabe desfazer

Vamos construir o roteiro da encomenda grande do capítulo 12 em Python puro, sem nenhuma biblioteca. O programa vai mostrar, rodando, as ideias que vimos lá:

- um passo depois do outro, com o estado salvo a cada passo concluído;
- uma parada à espera da aprovação da Dona Cida, que vale só para a versão que ela viu;
- a recusa de quem não tem autoridade para aprovar;
- uma queda no meio do caminho, com retomada sem cobrar o sinal duas vezes;
- o cancelamento, com as compensações de cada efeito.

## O armazém e os efeitos

O `Armazem` guarda o estado como texto, do jeito que um banco de dados guardaria. Isso obriga o programa a salvar e reler de verdade, em vez de manter tudo na memória. `Forno` e `Pix` são os dois sistemas que mexem no mundo, e os dois usam a chave de intenção do capítulo 7: pedido repetido devolve o mesmo resultado.

@CODE
import hashlib
import json

LIMITE_APROVACAO = 1000
AUTORIZADOS = {"dona_cida"}
FINAIS = {"Sucesso", "Falha", "Cancelado"}


class Armazem:
    """Guarda o estado como texto, como um banco."""

    def __init__(self):
        self.dados = {}

    def salvar(self, chave, estado):
        self.dados[chave] = json.dumps(estado)

    def ler(self, chave):
        return json.loads(self.dados[chave])


class Forno:
    def __init__(self):
        self.reservas = {}
        self.liberadas = set()

    def reservar(self, chave, dia):
        if chave not in self.reservas:
            numero = f"F{len(self.reservas) + 1}"
            self.reservas[chave] = numero
        return self.reservas[chave]

    def liberar(self, numero):
        self.liberadas.add(numero)


class Pix:
    def __init__(self):
        self.cobrancas = {}
        self.estornos = set()

    def gerar(self, chave, valor):
        if chave not in self.cobrancas:
            numero = f"PIX{len(self.cobrancas) + 1}"
            self.cobrancas[chave] = (numero, valor)
        return self.cobrancas[chave][0]

    def estornar(self, numero):
        self.estornos.add(numero)
@END

## Os passos

Cada passo recebe o estado e devolve uma de três respostas: seguir (com o que acrescentar ao estado), esperar ou falhar. A regra de aprovação é código, não opinião do modelo. A função `versao` tira uma "impressão digital" do pedido: qualquer mudança em quantidade, valor ou data muda a impressão, e a aprovação antiga deixa de valer.

@CODE
def versao(pedido):
    texto = json.dumps(pedido, sort_keys=True)
    return hashlib.sha256(texto.encode()).hexdigest()[:10]


def conferir(estado, ctx):
    p = estado["pedido"]
    if p["salgados"] <= 0 or p["andares"] <= 0:
        return "falhar", "quantidade inválida"
    return "seguir", {}


def calcular(estado, ctx):
    p = estado["pedido"]
    kg = p["salgados"] * 0.03 + p["andares"] * 1.5
    return "seguir", {"farinha_kg": round(kg, 1)}


def aprovar(estado, ctx):
    p = estado["pedido"]
    if p["valor"] <= LIMITE_APROVACAO:
        return "seguir", {"aprovado_por": "regra"}
    ap = estado.get("aprovacao")
    if ap is None:
        return "esperar", "aguardando a Dona Cida"
    if ap["versao"] != versao(p):
        return "esperar", "pedido mudou: aprovar de novo"
    return "seguir", {"aprovado_por": ap["quem"]}


def reservar(estado, ctx):
    p = estado["pedido"]
    chave = f"forno:{p['id']}:{p['dia']}"
    numero = ctx["forno"].reservar(chave, p["dia"])
    return "seguir", {"reserva": numero}


def cobrar(estado, ctx):
    p = estado["pedido"]
    chave = f"sinal:{p['id']}"
    valor = round(p["valor"] * 0.3, 2)
    numero = ctx["pix"].gerar(chave, valor)
    if ctx.get("cair_em") == "cobrar":
        ctx["cair_em"] = None
        raise RuntimeError("queda de energia")
    return "seguir", {"cobranca": numero}


PASSOS = [("conferir", conferir),
          ("calcular", calcular),
          ("aprovar", aprovar),
          ("reservar", reservar),
          ("cobrar", cobrar)]
@END

O passo `cobrar` tem um truque para o teste: quando `ctx["cair_em"]` pede, ele simula uma queda de energia **depois** de gerar o Pix e **antes** de o workflow salvar o passo. É o pior momento possível, o do capítulo 12: o efeito aconteceu, mas a confirmação não foi guardada.

## O controlador

O `Workflow` é o controlador do capítulo 4. Ele move os estados (Pronto, Em andamento, Bloqueado, Sucesso, Falha, Cancelado), salva o estado depois de cada passo e sabe retomar do ponto certo, porque o número do próximo passo também fica salvo.

@CODE
class Workflow:
    def __init__(self, armazem, ctx):
        self.armazem = armazem
        self.ctx = ctx

    def iniciar(self, pedido):
        estado = {"pedido": pedido, "passo": 0,
                  "status": "Pronto", "trilha": []}
        self.armazem.salvar(pedido["id"], estado)
        return self.rodar(pedido["id"])

    def rodar(self, id_pedido):
        estado = self.armazem.ler(id_pedido)
        if estado["status"] in FINAIS:
            return estado
        estado["status"] = "Em andamento"
        while estado["passo"] < len(PASSOS):
            nome, passo = PASSOS[estado["passo"]]
            acao, info = passo(estado, self.ctx)
            if acao == "esperar":
                estado["status"] = "Bloqueado"
                estado["motivo"] = info
                self.armazem.salvar(id_pedido, estado)
                return estado
            if acao == "falhar":
                estado["status"] = "Falha"
                estado["motivo"] = info
                self.armazem.salvar(id_pedido, estado)
                return estado
            estado.update(info)
            estado["trilha"].append(nome)
            estado["passo"] += 1
            self.armazem.salvar(id_pedido, estado)
        estado["status"] = "Sucesso"
        estado.pop("motivo", None)
        self.armazem.salvar(id_pedido, estado)
        return estado
@END

## Aprovar, alterar e cancelar

Três eventos vêm de fora. A aprovação confere quem aprova e registra a versão que a pessoa viu. A alteração só é aceita com o pedido parado, à espera de aprovação. O cancelamento aplica as compensações: libera a reserva do forno e estorna o sinal.

@CODE
    def versao_atual(self, id_pedido):
        estado = self.armazem.ler(id_pedido)
        return versao(estado["pedido"])

    def aprovar(self, id_pedido, quem, versao_vista):
        if quem not in AUTORIZADOS:
            raise PermissionError(f"{quem} não aprova")
        estado = self.armazem.ler(id_pedido)
        estado["aprovacao"] = {"quem": quem,
                               "versao": versao_vista}
        self.armazem.salvar(id_pedido, estado)
        return self.rodar(id_pedido)

    def alterar(self, id_pedido, **mudancas):
        estado = self.armazem.ler(id_pedido)
        if estado["status"] != "Bloqueado":
            raise ValueError("só altera pedido parado")
        estado["pedido"].update(mudancas)
        self.armazem.salvar(id_pedido, estado)
        return self.rodar(id_pedido)

    def cancelar(self, id_pedido):
        estado = self.armazem.ler(id_pedido)
        if "reserva" in estado:
            self.ctx["forno"].liberar(estado["reserva"])
        if "cobranca" in estado:
            self.ctx["pix"].estornar(estado["cobranca"])
        estado["status"] = "Cancelado"
        self.armazem.salvar(id_pedido, estado)
        return estado
@END

## Rodando a história inteira

@CODE
from casamento import Armazem, Forno, Pix, Workflow

armazem = Armazem()
ctx = {"forno": Forno(), "pix": Pix()}
wf = Workflow(armazem, ctx)

pedido = {"id": "E42", "salgados": 200,
          "andares": 3, "dia": "14/11", "valor": 1400}

e = wf.iniciar(pedido)
print("1.", e["status"], "-", e["motivo"])

vista = wf.versao_atual("E42")   # Dona Cida lê
e = wf.alterar("E42", salgados=300, valor=1900)
e = wf.aprovar("E42", "dona_cida", vista)
print("2.", e["status"], "-", e["motivo"])

try:
    wf.aprovar("E42", "julia", wf.versao_atual("E42"))
except PermissionError as erro:
    print("3. recusado:", erro)

ctx["cair_em"] = "cobrar"
try:
    nova = wf.versao_atual("E42")
    wf.aprovar("E42", "dona_cida", nova)
except RuntimeError as erro:
    print("4. caiu:", erro)

wf2 = Workflow(armazem, ctx)   # sistema reiniciado
e = wf2.rodar("E42")
print("5.", e["status"], e["reserva"], e["cobranca"])
print("   passos:", ", ".join(e["trilha"]))
print("   cobranças feitas:", len(ctx["pix"].cobrancas))

e = wf2.cancelar("E42")
print("6.", e["status"], "| forno liberado:",
      ctx["forno"].liberadas, "| estorno:",
      ctx["pix"].estornos)
@END

2. Bloqueado - pedido mudou: aprovar de novo

## O que falta para produção

Este workflow cabe em poucas páginas, mas o esqueleto é o de sistemas bem maiores. Numa padaria de verdade, faltariam um banco de dados de verdade no lugar do `Armazem`, prazos para a espera da aprovação, novas tentativas com espera crescente para erros passageiros e um registro de quem aprovou o quê, com data e hora. Ferramentas prontas de workflow durável, como Temporal, LangGraph ou o Microsoft Agent Framework, oferecem boa parte disso, e o capítulo 25 ajuda a escolher.

@RESUMO
O estado é salvo a cada passo concluído; retomar é ler o último ponto salvo e seguir.
Regras exatas, como o limite de aprovação, são código.
A aprovação guarda quem aprovou e a versão aprovada; pedido alterado pede aprovação nova.
A chave de intenção impede que a retomada repita efeitos.
Cancelar é compensar cada efeito já feito.
@END
